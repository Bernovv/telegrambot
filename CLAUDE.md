# telegrambot — правила работы в репозитории

Продажа билетов на мероприятия Бизнес-Прорыва. Боевые деньги через Т-Банк, боевые данные
покупателей. Монорепо pnpm: `apps/` (bot, api, worker, admin-web) и `packages/` (domain,
application, database, contracts, messenger-*).

Полный контекст проекта, инфраструктура сервера и порядок выкладки — в репозитории
`LovePashian/businessProriv` (файлы `CLAUDE.md`, `План_интеграции_каналов.md`,
`СОСТОЯНИЕ_И_ЗАДАЧИ.md`). Здесь — то, без чего нельзя трогать код.

## Сквозной принцип

**Деньги и согласия покупателей нельзя терять и переписывать задним числом.** Отсюда
неизменяемые версии оферты, снимки цен в заказах, журнал доставок, append-only ленты
касаний и отказ удалять оплаченные заказы.

## Проверки перед коммитом

```bash
pnpm typecheck && pnpm lint && pnpm test
```

Для миграций дополнительно:

```bash
pnpm db:migrations:check && pnpm db:sql:check
```

`db:sql:check` ловит запросы, где один параметр подставляется в колонки разных типов. Такая
ошибка дважды за вечер роняла боевые события, а обычные тесты её не видят: настоящей базы в
них нет.

**Если правился SQL — ещё и `pnpm db:smoke`.** Он выполняет по настоящей базе каждый запрос,
который панель зовёт при обычной работе, и ловит колонку, которой нет в подзапросе. Postgres
отвергает такой запрос целиком — страница отдаёт 500. Нужна пустая **не боевая** база:

```bash
initdb -D /tmp/pgsmoke -U postgres --auth=trust
pg_ctl -D /tmp/pgsmoke -o "-k /tmp -p 55432 -c listen_addresses=" -l /tmp/pgsmoke.log start
createdb -h /tmp -p 55432 -U postgres smoke
for f in supabase/migrations/*.sql; do psql -h /tmp -p 55432 -U postgres -d smoke -v ON_ERROR_STOP=1 -q -f "$f"; done
SMOKE_DATABASE_URL="postgresql://postgres@localhost:55432/smoke?host=/tmp" pnpm db:smoke
```

База при этом пустая, и в этом её предел: **миграция, которая правит уже существующие
строки, на пустой базе проходит всегда** — править нечего. Такую проверяют, налив похожие
данные руками.

## Чего нельзя делать

- **Не редактировать применённую миграцию** — только новая миграция поверх.
- **Не удалять оплаченные заказы, билеты и проводки кошелька** — это финансовая история.
- **Не подменять файл оферты по существующему адресу** — новая редакция это новая версия в
  `offer_versions` со своей контрольной суммой, иначе старые согласия перестают
  соответствовать документу.
- **Не ломать append-only.** `outreach_activities` и журнал доставок защищены триггерами
  намеренно.
- **Не загружать `.env` командой `. ./.env`** — в пароле Т-Банка есть `&`, шелл ломается.
- **Не перезапускать бота, не убедившись, что `TELEGRAM_API_ROOT` на месте** — без прокси
  Telegram с боевого сервера недоступен. Копирование `.env` поверх серверного однажды стёрло
  адрес прокси и на два часа положило доставку.

## Чего в репозитории нет

`.env` в git не лежит и лежать не должен. Значит, без него **нельзя**: запускать бота, api,
воркер, применять миграции к боевой базе, гонять `db:smoke` по боевым данным. **Можно**:
типы, линт, тесты, сборка панели, `db:smoke` по локальной пустой базе.

## Порядок выкладки

Прямого доступа к серверу и GitHub у Claude нет. Цепочка одна: правка и коммит локально →
push делает владелец → на сервере merge и перезапуск. **После каждой правки сразу давать
готовые команды выкладки** — что запустить на сервере и в каком порядке. Миграции
применяются **до** перезапуска процессов. Если правка ничего не требует на сервере
(документация, тесты) — сказать об этом прямо.

Таблица «что менялось → что перезапустить» — в `CLAUDE.md` внешнего репозитория.
