# Как запустить продажи билетов через Telegram-бота

Инструкция для запуска бота в реальную работу: человек открывает бота, смотрит
программу мероприятия и покупает билет с оплатой картой. Анкета после оплаты,
напоминания о мероприятии и админ-панель — намеренно отключены, включим позже
отдельным шагом.

Если какой-то шаг непонятен — пришлите мне, что видите на экране (или текст
ошибки), и я подскажу, что делать дальше.

## Что уже готово

- Весь код бота: меню, выбор билета, расчёт цены со скидкой за количество,
  оформление заказа, оферта, оплата — включая партнёрскую программу (бонусы за
  приглашённых работают сразу, отдельно включать не нужно).
- Мероприятие и цены уже в базе данных (миграцией) — «Бизнес-Пикник 8–9 августа
  2026», все 5 видов билетов с ценами из ваших документов.
- Готовый файл `.env` с вашими реальными данными (токен бота, реквизиты Т-Банка —
  те же боевые, что уже работают у MAX-бота) — лежит в этой же папке проекта у
  меня, **в git его нет и не будет** (специально проверила — он в списке
  игнорируемых файлов). `deploy/production.env.template` рядом — это просто
  пустой образец без секретов, для справки.
- Username бота (`@businessProriv_bot`) уже вписан в `.env`.
- В `.env` уже исправлены два момента, которые вскрылись из присланных вами данных:
  - адрес базы данных — приватный `192.168.0.4` оказался недоступен с сервера
    (таймаут при подключении), поэтому используем публичный `83.217.192.57` с
    `sslmode=require` — так же, как уже работает у MAX-бота;
  - порт — у MAX-бота процесс уже занимает `3000`, поэтому наш бот теперь
    настроен на порт `3001`, чтобы не было конфликта. Осталось только один раз
    поправить nginx (Пункт B ниже), чтобы платежи от Т-Банка доходили до порта `3001`.

Работаем сразу в боевом режиме (не тестовом) — раз реквизиты Т-Банка боевые.
Первую покупку после запуска сделаем на минимальную сумму и проверим вручную.

## Пункт A. Отдельная база данных (сделать один раз)

`postgresql-client` вы уже установили. Приватный адрес `192.168.0.4` оказался
недоступен с этого сервера (была ошибка `Connection timed out`) — используем
публичный адрес, тот же, что уже работает у MAX-бота:

```bash
PGPASSWORD='l2=otTm3^k<Y2e' psql -h 83.217.192.57 -U gen_user -d default_db -c "CREATE DATABASE telegram_bot_db;"
```

Должно вывести `CREATE DATABASE`. Пришлите мне результат — если ошибка, разберёмся.

## Пункт B. Домен для приёма платежей (правка nginx)

У MAX-бота уже есть рабочий домен с HTTPS: `max-bot.biz-day.ru`, его процесс
слушает порт `3000`. Наш бот настроен на порт `3001` (чтобы не конфликтовать),
поэтому вешаем на тот же домен ещё один путь (`/webhooks/payments/tbank`),
который будет вести на порт `3001`. Новый домен и новый SSL-сертификат не нужны.

Сначала узнайте точное имя файла конфига:

```bash
ls -la /etc/nginx/sites-enabled/
```

Откройте его в редакторе (замените `ИМЯ_ФАЙЛА` на то, что увидели выше):

```bash
sudo nano /etc/nginx/sites-enabled/ИМЯ_ФАЙЛА
```

Внутри найдите блок `server { ... }`, где есть строка `server_name max-bot.biz-day.ru;`
**и** `listen 443 ssl` (это блок с HTTPS, не тот, что просто редиректит с 80 на 443).
В этом блоке, до существующего `location / { ... }`, добавьте новый блок:

```nginx
    location /webhooks/payments/tbank {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`), затем проверьте и примените:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

`sudo nginx -t` должен вывести `syntax is ok` и `test is successful` — если
там ошибка, пришлите мне текст целиком, ничего не перезагружайте.

## Шаг 1. Скопировать код и настройки на сервер

Выполняется на сервере `spb-3-vm-yjv2` (там же, где MAX-бот), в домашней папке
пользователя `maxbot` — рядом с `max-bot`, но в **отдельной** папке:

```bash
cd ~
git clone https://github.com/Bernovv/telegrambot.git
cd telegrambot
git checkout codex/phase-1-foundation
git pull
```

Дальше нужно перенести уже готовый файл `.env` (лежит в этом проекте у меня на
вашем компьютере, рядом с этой инструкцией — НЕ файл `deploy/production.env.template`,
тот пустой) в корень `telegrambot` на сервере. Проще всего — открыть файл `.env`
у себя на компьютере, скопировать весь текст, затем на сервере:

```bash
nano .env
# вставьте скопированный текст, затем Ctrl+O, Enter, Ctrl+X чтобы сохранить
```

**Файл `.env` никогда никому не показывайте и не выкладывайте в открытый доступ.**

## Шаг 4. Запустить бота

В папке `deploy/` уже лежат три готовых скрипта запуска:

```bash
npm install -g pm2
chmod +x deploy/run-bot.sh deploy/run-api.sh deploy/run-worker.sh

pm2 start deploy/run-bot.sh --name bot
pm2 start deploy/run-api.sh --name api
pm2 start deploy/run-worker.sh --name worker

pm2 save
pm2 startup   # выведет команду — выполните её, чтобы pm2 поднимался после перезагрузки сервера
pm2 logs
```

Проверка:
- отправьте боту `/start` в Telegram — должно прийти приветственное меню;
- `pm2 status` — все три процесса (`bot`, `api`, `worker`) должны быть `online`,
  а не `errored`;
- `pm2 logs --lines 30` — не должно быть повторяющихся ошибок подключения к базе.

## Шаг 5. Первая проверочная покупка (реальные деньги)

Реквизиты Т-Банка боевые, поэтому это будет настоящая транзакция:

1. `/start` → «Купить билет» → любой тип → 1 штука.
2. «Принять оферту» → «Оплатить» → оплатите картой сумму этого билета.
3. Бот должен прислать билет с QR-кодом.
4. Если всё сработало — вернуть эти деньги себе можно через личный кабинет
   Т-Банка (раздел операций/платежей, там есть возврат по операции), это не
   влияет на код бота.

Если билет не пришёл — пришлите мне `pm2 logs`, разберёмся.
