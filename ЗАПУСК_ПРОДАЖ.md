# Как запустить продажи билетов через Telegram-бота

Эта инструкция — пошаговый план для запуска бота в реальную работу: человек открывает
бота, смотрит программу мероприятия и покупает билет с оплатой картой. Анкета после
оплаты, напоминания о мероприятии и админ-панель — намеренно отключены, включим позже
отдельным шагом, когда продажи уже пойдут.

Если какой-то шаг непонятен — пришлите мне, что видите на экране (или текст ошибки), и
я подскажу, что делать дальше.

## Что уже готово

- Весь код бота: меню, выбор билета (Стандарт / Всё включено / Детский / Семейный),
  расчёт цены со скидкой за количество, оформление заказа, оферта, оплата.
- Само мероприятие и цены уже занесены в базу данных (миграцией) — ничего вручную
  вбивать не нужно: «Бизнес-Пикник 8–9 августа 2026», все 5 видов билетов с ценами
  из ваших документов.
- Готовый шаблон настроек — файл `deploy/production.env.template` в этой же папке.

Дальше нужны 4 вещи от вас: доступ к оплате через Т-Банк, база данных, домен с HTTPS
для приёма платежей и сервер, где всё это запустить (у вас уже есть Timeweb).

---

## Шаг 1. Данные для приёма оплаты (Т-Банк)

Это отдельный процесс на стороне банка, я не могу сделать его за вас.

1. Зайдите в личный кабинет Т-Банк Бизнес → раздел «Приём платежей» / «Эквайринг».
2. Если у вас ещё нет подключённого интернет-эквайринга — оформите заявку (обычно
   рассматривают 1–3 рабочих дня).
3. После подключения в кабинете появятся:
   - **Terminal Key** (ключ терминала),
   - **Пароль терминала**.
4. Сохраните оба значения — они понадобятся в шаге 4.

Пока заявка на рассмотрении, можно продолжать остальные шаги — тестовый режим
позволяет проверить всю цепочку без реальных денег.

---

## Шаг 2. База данных

Вы говорили, что база (Postgres) уже есть, но не Supabase. Нужна строка подключения к
ней — обычно она выглядит так:

```
postgresql://пользователь:пароль@адрес-сервера:5432/имя_базы
```

Если базу выдавал Timeweb — она есть в панели управления Timeweb, в разделе с базами
данных (там будет «Хост», «Порт», «Пользователь», «Пароль», «Имя базы» — из них и
собирается строка выше). Если базу настраивали не вы — попросите того, кто настраивал,
прислать эту строку.

---

## Шаг 3. Домен с HTTPS

Т-Банк должен иметь возможность «постучаться» на ваш сервер и сказать «оплата прошла».
Для этого нужен домен, который смотрит на ваш сервер, с включённым HTTPS (замочек в
браузере). Если у вас уже настроен домен для MAX-бота на Timeweb — скорее всего,
можно использовать его же (например, добавить отдельный путь вроде
`https://ваш-домен.ru/webhooks/payments/tbank`).

Если домена с HTTPS ещё нет — в Timeweb есть готовые инструкции по подключению домена
и бесплатному SSL-сертификату (Let's Encrypt) прямо из панели управления. Это разовая
настройка на 10–15 минут.

---

## Шаг 4. Заполнить настройки

1. Скопируйте файл `deploy/production.env.template` в корень проекта под именем `.env`
   (`cp deploy/production.env.template .env`).
2. Откройте `.env` и замените все места, где написано «ЗАПОЛНИТЬ»:
   - `DATABASE_URL` и `DATABASE_DIRECT_URL` — строка из шага 2 (обычно одна и та же
     строка в оба поля);
   - `TELEGRAM_BOT_TOKEN` — токен вашего бота от @BotFather (он у вас уже есть);
   - `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD` — из шага 1;
   - `TBANK_NOTIFICATION_URL` — `https://ваш-домен.ru/webhooks/payments/tbank`;
   - `TBANK_SUCCESS_URL` и `TBANK_FAIL_URL` — можно указать ссылку на бота:
     `https://t.me/имя_вашего_бота`;
   - `ADMIN_NOTIFICATION_TELEGRAM_CHAT_ID` — см. шаг 6 ниже, можно заполнить позже.
3. Остальное менять не нужно — там уже безопасные готовые значения (в том числе
   секретные ключи для заказов и билетов — они сгенерированы случайно специально для
   вас).

**Файл `.env` никогда никому не показывайте и не выкладывайте в открытый доступ** — в
нём будут пароли и ключи от оплаты.

## Шаг 5. Разместить код на сервере и подготовить базу

Дальше нужен доступ к серверу Timeweb по SSH (то же самое, через что разворачивали
MAX-бота). Если это делаете не вы лично, а помощник/разработчик — просто передайте ему
эту инструкцию начиная с этого шага.

```bash
# 1. Скачать код на сервер (если ещё не скачан)
git clone https://github.com/Bernovv/telegrambot.git
cd telegrambot
git checkout codex/phase-1-foundation
git pull

# 2. Положить рядом с корнем проекта заполненный .env (шаг 4)

# 3. Установить зависимости (сборка не нужна — процессы запускаются напрямую
#    из исходников через tsx, см. Шаг 7)
corepack pnpm install --frozen-lockfile --filter '!admin-web'

# 4. Применить миграции (создать все таблицы в вашей базе данных)
set -a; source .env; set +a
corepack pnpm db:migrate:deploy
```

Если на этом шаге появится сообщение об ошибке — пришлите мне текст целиком, разберём.

---

## Шаг 6. Узнать свой Telegram chat_id (для уведомлений о продажах)

Хотите получать сообщение в Telegram о каждой новой покупке — понадобится ваш
числовой chat_id:

1. Напишите в Telegram боту `@userinfobot` — он пришлёт в ответ ваш `Id`.
2. Впишите это число в `.env` в строку `ADMIN_NOTIFICATION_TELEGRAM_CHAT_ID`.

Если пропустить этот шаг — бот всё равно будет продавать билеты, просто вы не будете
получать личные уведомления о каждой покупке.

---

## Шаг 7. Запустить бота

Нужно запустить **три процесса одновременно** (проще всего — через `pm2`, менеджер
процессов для Node.js, который сам перезапускает их при сбое или перезагрузке
сервера):

В папке `deploy/` уже лежат три готовых скрипта запуска — их не нужно писать
самостоятельно, просто сделать их исполняемыми и запустить через pm2:

```bash
npm install -g pm2
chmod +x deploy/run-bot.sh deploy/run-api.sh deploy/run-worker.sh

# Запускать из корня проекта (папки telegrambot), .env должен лежать там же
pm2 start deploy/run-bot.sh --name bot
pm2 start deploy/run-api.sh --name api
pm2 start deploy/run-worker.sh --name worker

pm2 save
pm2 startup   # выведет команду — выполните её, чтобы pm2 поднимался после перезагрузки сервера
pm2 logs
```

`pm2 logs` покажет, что происходит внутри — если что-то пошло не так, там будет видно
сообщение об ошибке.

Проверка, что всё работает:
- откройте вашего бота в Telegram и отправьте `/start` — должно прийти приветственное
  меню с кнопками;
- откройте в браузере `https://ваш-домен.ru/health/live` — должно вернуться `ok`.

## Шаг 8. Тестовая покупка (без реальных денег)

Пока `TBANK_API_BASE_URL` указывает на тестовый адрес (`rest-api-test.tinkoff.ru`),
деньги по-настоящему не списываются. Пройдите весь путь сами:

1. `/start` → «Купить билет» → выберите тип билета → укажите количество.
2. Нажмите «Принять оферту».
3. Нажмите «Оплатить» — откроется страница Т-Банка.
4. Введите тестовые данные карты (Т-Банк выдаёт их вместе с тестовым доступом —
   уточните в личном кабинете, если не прислали автоматически).
5. После оплаты бот должен прислать билет с QR-кодом.

Если билет не пришёл — значит, скорее всего, не запущен `worker` (шаг 7) или не
настроен `TBANK_NOTIFICATION_URL` (шаг 4/3) — пришлите мне `pm2 logs`, разберёмся.

---

## Шаг 9. Переключение на приём реальных денег

Когда Т-Банк подтвердит боевой (продакшн) доступ, в `.env` нужно поменять **вместе, за
один раз** три строки (система специально не даст запуститься, если поменять только
часть из них — это защита от случайной боевой оплаты через тестовые настройки):

1. `APP_ENV=production` (было `staging`).
2. `TBANK_API_BASE_URL=https://securepay.tinkoff.ru/v2` (было `rest-api-test...`).
3. Боевые `TBANK_TERMINAL_KEY` и `TBANK_PASSWORD` от Т-Банка (обычно отличаются от
   тестовых — уточните у менеджера Т-Банка).

Затем:

4. Перезапустите все три процесса: `pm2 restart bot api worker`.
5. Сделайте одну реальную покупку на минимальную сумму (можно самому себе), проверьте,
   что деньги дошли и билет пришёл — и можно объявлять о старте продаж.

## Что осталось «на потом» (не блокирует запуск)

Эти вещи специально отключены сейчас, чтобы не задерживать запуск. Включим по
готовности отдельным шагом, без переустановки:

- анкета участника после оплаты (7 вопросов);
- напоминания о мероприятии за 10/7/3/1 день;
- админ-панель (admin-web) для управления мероприятиями через браузер;
- рассылки и CSV-экспорт участников для администратора.

Партнёрская программа (реферальные ссылки, бонусы за приглашённых) уже работает "из
коробки" вместе с покупкой билета — отдельно включать не нужно.
