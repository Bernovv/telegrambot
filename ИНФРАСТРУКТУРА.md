# Как устроен сервер — где что лежит и как работает

Справочник по продакшн-окружению Telegram-бота продажи билетов. Если что-то
здесь устарело после будущих изменений — поправьте заодно и этот файл.

## Сервер

- Хостинг: **Timeweb**, VM с именем `spb-3-vm-yjv2` (Санкт-Петербург).
- На этом же сервере уже жил и продолжает работать **MAX-бот** (другой проект,
  для мессенджера MAX, не Telegram) — он не трогается, всё новое ставилось
  рядом, в отдельных папках/процессах/базе, чтобы не задеть его работу.
- Заходить на сервер — по SSH, под пользователем `root` (или `maxbot`, если
  так исторически настроен доступ).

## Где лежит код

- Наш проект: `~/telegrambot` (папка `/root/telegrambot`, если зашли под root).
- MAX-бот: `~/max-bot` (соседняя папка, не наша зона ответственности).
- Репозиторий: `https://github.com/Bernovv/telegrambot.git`, рабочая ветка
  `codex/phase-1-foundation`.
- Файл с реальными секретами: `~/telegrambot/.env` — **не в git**
  (`.gitignore` это гарантирует). Копия этого файла также лежит у вас на
  компьютере в папке `BusinessProriv/telegrambot/.env` — именно оттуда его
  надо копировать на сервер, если он меняется.

### Как обновить код на сервере

Я (Claude) не могу пушить в GitHub напрямую — нет доступа. Поэтому цепочка
всегда такая:

1. Я вношу изменения в код у себя и коммичу.
2. **Вы** с компьютера пушите: `cd ~/Documents/BusinessProriv/telegrambot && git push origin codex/phase-1-foundation`.
3. На сервере: `cd ~/telegrambot && git pull`.
4. Перезапускаете нужный процесс через `pm2 restart <имя>` (см. ниже).

## Node.js — две версии на одном сервере

- Системный Node (из `apt`, версия 20.x) — использует **MAX-бот**. Не трогаем.
- Наш проект требует Node **24+**. Поставлен отдельно через `nvm` в
  `~/.nvm`, никак не пересекается с системным.
- Скрипты запуска (`deploy/run-bot.sh`, `run-api.sh`, `run-worker.sh`) сами
  подключают nvm и Node 24 внутри себя — поэтому неважно, что стоит в PATH
  снаружи, конфликта с MAX-ботом не будет.

## База данных

Не используем ни приватный, ни публичный адрес управляемой базы Timeweb,
которой пользуется MAX-бот (`default_db`) — по двум причинам:

1. Тариф Timeweb разрешает только одну базу в этом managed-кластере — создать
   вторую нельзя без платного апгрейда.
2. У `default_db` та же доменная модель, что и у нашего проекта (`users`,
   `orders`, `wallet_accounts` и т.д. с реальными данными MAX-бота) — писать
   туда нашими миграциями было бы опасно.

Поэтому на сервере установлен **свой, отдельный Postgres** (версия 18, через
`apt install postgresql`), который слушает только `127.0.0.1:5432` — то есть
доступен исключительно с этого же сервера, снаружи недоступен.

- База: `telegram_bot_db`
- Пользователь: `telegram_bot_app`
- Пароль: см. `.env` → `DATABASE_URL`
- Строка подключения в `.env`:
  `DATABASE_URL=postgresql://telegram_bot_app:<пароль>@127.0.0.1:5432/telegram_bot_db`

Проверить подключение вручную:

```bash
PGPASSWORD='<пароль_из_.env>' psql -h 127.0.0.1 -U telegram_bot_app -d telegram_bot_db -c "\dt"
```

Применить миграции (если появятся новые):

```bash
cd ~/telegrambot
export NVM_DIR="$HOME/.nvm"; [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
node --env-file=.env --import tsx packages/database/scripts/migrate.ts deploy
```

## Три процесса приложения

Запускаются и живут через **pm2** (общий с MAX-ботом демон — `pm2 status`
покажет процессы обоих проектов сразу, это нормально):

| Имя в pm2 | Что делает | Скрипт запуска |
|---|---|---|
| `bot` | Сам Telegram-бот: меню, покупка билета в чате, long-polling | `deploy/run-bot.sh` |
| `api` | Принимает вебхуки об оплате от Т-Банка, слушает `127.0.0.1:3001` | `deploy/run-api.sh` |
| `worker` | Фоновые задачи: доставка билета после оплаты, уведомления, снятие брони, напоминания | `deploy/run-worker.sh` |

Полезные команды:

```bash
pm2 status                              # статус всех процессов (наших и MAX-бота)
pm2 logs bot --lines 50 --nostream      # последние логи бота
pm2 logs api --lines 50 --nostream
pm2 logs worker --lines 50 --nostream
pm2 restart bot api worker              # перезапустить все три после обновления кода/.env
pm2 save                                # сохранить текущий список процессов (чтобы поднялись после перезагрузки сервера)
```

Порт `3000` занят MAX-ботом, поэтому наш `api` — на `3001`, чтобы не было
конфликта.

## nginx и домен

Отдельного домена для нашего бота нет и не нужно — используется уже готовый
домен MAX-бота `max-bot.biz-day.ru` (HTTPS уже настроен через Let's Encrypt).
В конфиг nginx (`/etc/nginx/sites-available/max-bot`) добавлен ещё один
`location`, специально для приёма платёжных вебхуков от Т-Банка:

```nginx
location /webhooks/payments/tbank {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Т-Банк присылает уведомления об оплате на
`https://max-bot.biz-day.ru/webhooks/payments/tbank`, nginx перенаправляет их
на наш процесс `api` (порт 3001). Общий `location /` в этом же файле
по-прежнему ведёт на MAX-бота (порт 3000) — эти два `location` не мешают друг
другу (более специфичный путь у nginx всегда в приоритете).

Проверка/применение изменений конфига:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## Telegram API заблокирован — прокси через Cloudflare Worker

С этого сервера (РФ) `api.telegram.org` недоступен напрямую (таймауты).
Решение — бесплатный Cloudflare Worker, который просто перекладывает запросы
в Telegram (сам Cloudflare для российских провайдеров не заблокирован):

- Код воркера: `deploy/cloudflare-telegram-proxy.js` в репозитории (для
  справки/пересоздания, если понадобится).
- Адрес развёрнутого воркера прописан в `.env` → `TELEGRAM_API_ROOT`.
- Секретов внутри воркера нет — токен бота передаётся в самом URL запроса,
  как обычно у Telegram Bot API, воркер его не хранит.
- Если воркер когда-нибудь пересоздадите — обновите `TELEGRAM_API_ROOT` в
  `.env` на новый адрес и сделайте `pm2 restart bot api worker`.

## Оплата (Т-Банк)

- Терминал — тот же боевой, что уже используется у MAX-бота (реквизиты в
  `.env`: `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD`).
- Адрес для уведомлений об оплате: `TBANK_NOTIFICATION_URL` →
  `https://max-bot.biz-day.ru/webhooks/payments/tbank` (см. раздел nginx выше).
- `TBANK_SUCCESS_URL` / `TBANK_FAIL_URL` ведут обратно в бота (`t.me/businessProriv_bot`).

## Уведомления администратору

При каждой покупке бот шлёт сообщение на chat_id из `.env` →
`ADMIN_NOTIFICATION_TELEGRAM_CHAT_ID` (можно несколько через запятую — сейчас
там два получателя).

## Если что-то не работает — с чего начать

1. `pm2 status` — все три процесса (`bot`, `api`, `worker`) должны быть
   `online`, счётчик `↺` не должен расти на глазах (это значит процесс
   постоянно падает и перезапускается).
2. `pm2 logs <имя> --lines 50 --nostream` — смотреть на `error.log`, там
   теперь пишется не только тип ошибки, но и текст сообщения.
3. Проверить, что `.env` на сервере совпадает с тем, что должно быть (частая
   причина проблем — забыли обновить `.env` на сервере после того, как он
   поменялся локально). `grep -n ИМЯ_ПЕРЕМЕННОЙ .env` — если пусто, значит
   переменной нет вообще (например, `sed` по отсутствующей строке ничего не
   сделает и не пожалуется).
4. Проверка доступности Telegram через прокси:
   `curl -s "$(grep TELEGRAM_API_ROOT .env | cut -d= -f2)/bot$(grep TELEGRAM_BOT_TOKEN .env | cut -d= -f2)/getMe"`
   — должен вернуть `{"ok":true,...}`.
