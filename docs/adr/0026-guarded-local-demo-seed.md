# ADR 0026: Защищенное демонстрационное наполнение local/test

## Статус

Принято.

## Контекст

Исходная документация требует воспроизводимый локальный стенд с тестовыми пользователями,
мероприятием Business Picnic, ценами, сценарием и тестовым способом оплаты. Ранее `seed.sql`
создавал только кампанию телефонного бонуса, а команды `db:seed` не существовало.

Seed нельзя применять к staging или production. Повторный запуск не должен перезаписывать данные,
которые администратор изменил при ручной проверке. Создание администратора также нельзя смешивать
с seed: учетная запись сначала должна существовать в выбранном Supabase Auth.

## Решение

- `db:seed` разрешен только при `APP_ENV=local` или `APP_ENV=test` и точной фразе
  `DATABASE_SEED_CONFIRM=seed-local-demo-data`.
- Команда использует прямое подключение PostgreSQL, отдельный неблокирующий advisory lock и одну
  транзакцию.
- SQL содержит только `INSERT`, `CREATE TEMPORARY TABLE` и чтение. `UPDATE`, `DELETE`, `TRUNCATE`,
  destructive `DROP` и `ALTER TABLE` блокируются до подключения к базе.
- Демо-сущности используют фиксированные UUID и синтетические контакты. Дочерний набор создается
  только если корневой пользователь или мероприятие были вставлены в текущем запуске.
- При повторном запуске существующие строки не меняются. Запускатель проверяет ожидаемые количества
  и завершает работу с ошибкой, если набор был вручную изменен или частично удален.
- Фактический graph сценария читается обратно из PostgreSQL и проверяется штатным
  `validateScenarioGraph` до commit.
- Мероприятие, документ оферты и версия сценария остаются черновиками. Публикация выполняется через
  audited application service после создания реального immutable snapshot оферты.
- Локальный администратор создается отдельной `admin:bootstrap` после регистрации пользователя в
  Supabase Auth.

## Последствия

Локальная админка получает предсказуемые данные каталога без ручного SQL. Seed не является
восстановлением или синхронизацией: измененный демо-набор намеренно не чинится повторным запуском.
Для чистого повторения требуется новая пустая local/test база.

Fake payment provider пока не добавляется этим решением. Для проверки финансового перехода
доступна ручная MFA-операция, а интеграция Т-Банка остается выключенной по умолчанию.

## Откат

Код и seed-файл можно откатить. Автоматическое удаление уже созданных строк запрещено; local/test
база сбрасывается только отдельной явно подтвержденной операцией среды разработки.
