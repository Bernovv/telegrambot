# ADR 0021: Создание заказа из закрепленного сценария

## Статус

Принято.

## Контекст

Опубликованный Telegram-сценарий должен создавать реальный заказ после валидированного ввода
количества, показывать неизменяемую оферту и продолжаться к оплате после подтверждения владельцем.
Нельзя дублировать правила тарифов, вместимости, резервов и идемпотентности внутри runtime.

## Решение

- Legacy-вариант `order_start` содержит валюту и ограниченное отображение
  `productId → quantityContextKey`. Вариант `mode: "compose"` открывает ограниченный черновик,
  который изменяется узлами `order_add_item` и фиксируется узлом `order_summary`.
- `walletMode` определяет применение внутреннего баланса: `none` сохраняет историческое
  поведение, `all` резервирует доступную сумму через общий сервис создания заказа.
- Публикация требует один автоматический переход, корректные UUID, безопасные ключи контекста,
  уникальные продукты и не более 20 позиций.
- Оферта и оплата допустимы только после `order_start` на каждом пути; оплата также требует
  предшествующую `offer_acceptance`.
- Runtime вызывает общий `CreateOrderService` через application-порт. Сценарий не читает таблицы
  каталога, тарифов или заказов напрямую.
- Репозиторий сценария, репозиторий продаж, outbox и unit of work используют один
  `TransactionSession`. Заказ, резерв, событие outbox, контекст и переход сессии фиксируются одной
  транзакцией.
- Идемпотентный ключ заказа строится из сессии, узла и версии блокировки. В контексте хранится
  безопасный снимок идентификатора, публичного токена, статуса, сроков и строк целых копеек.
- Принятие оферты остается отдельной транзакцией. После нее runtime ищет не более одной открытой
  сессии по владельцу, точному `orderId` и узлу `offer_acceptance` с блокировкой `FOR UPDATE`.
- Денежные суммы не преобразуются в JavaScript `number`; форматирование выполняется через
  `BigInt`.

## Последствия

- Повтор update или callback не создает второй заказ и не продвигает чужую сессию.
- Изменение тарифа после создания не меняет снимок и сумму заказа.
- Новая публикация сценария не влияет на уже начатую сессию.
- Составной заказ применяет внутренний баланс и создает неизменяемый снимок только на
  `order_summary`; опубликованные legacy-сценарии продолжают работать без изменения payload.
- Бесплатные и полностью оплачиваемые балансом заказы подтверждаются внутренним платежным
  событием по ADR 0027 без обращения к Т-Банку.

## Откат

Код можно откатить без миграции: дополнительные данные находятся в существующем JSONB-контексте,
а таблицы заказов и сценариев не менялись. Уже созданные заказы остаются действительными и
обрабатываются общими сервисами оферты, оплаты и истечения.
