# ADR 0038. Версионированная персонализация рассылок

## Статус

Принято.

## Контекст

Текст рассылки должен поддерживать обращение к получателю, но результат обязан оставаться
воспроизводимым после изменения профиля. Существующие версии schema v1 опубликованы как обычный
текст и могут содержать фигурные скобки, поэтому включать интерпретацию для них нельзя.

## Решение

- Новые и повторно сохранённые черновики используют schema v2.
- В тексте разрешены только `{{first_name}}`, `{{last_name}}`, `{{display_name}}` и
  `{{telegram_username}}`.
- Версия хранит одно обязательное запасное обращение длиной до 64 символов. Оно используется для
  отсутствующего, пустого или некорректного значения.
- Кнопки, подписи кнопок и URL не поддерживают переменные.
- Schema v1 отправляется буквально и никогда не интерпретирует шаблоны.
- Массовая доставка фиксирует имя, фамилию, отображаемое имя и Telegram username в
  `personalization_context` при материализации delivery ledger.
- Тестовая доставка фиксирует тот же контекст при постановке в очередь.
- Worker рендерит копию содержимого непосредственно перед Telegram-вызовом. Исходная версия и
  контекст в журнале не изменяются.
- Результат длиннее 4096 символов получает окончательную ошибку
  `BroadcastPersonalizationOutputTooLong` без внешнего вызова.
- Неизвестный или повреждённый шаблон получает окончательную ошибку
  `BroadcastPersonalizationInvalid`.

## Последствия

- Уже подготовленная кампания не меняет обращения после редактирования профиля пользователя.
- Повторная попытка одной delivery-записи использует тот же контекст.
- Профильные значения сохраняются в delivery ledger и требуют тех же ограничений доступа и срока
  хранения, что и остальные персональные данные получателя.
- Запасное обращение может повториться для разных переменных; оператор должен проверять текст
  тестовой отправкой.

## Совместимость

Миграция `20260731000000_broadcast_personalization_v2` расширяет допустимые версии с 1 до 2 и
добавляет JSON-контекст в журналы доставки. Триггеры заполняют контекст и для старого процесса
подготовки во время rolling deploy. Опубликованные строки schema v1 не изменяются.
