# ADR 0042. Версионируемые решения по строкам импорта пользователей

## Статус

Принято.

## Контекст

Неизменяемый анализ CSV может пометить строку как `POSSIBLE_MATCH` или `CONFLICT`. Автоматически
создавать пользователя либо объединять данные в этих случаях небезопасно: предварительные признаки
могут быть устаревшими, а два администратора могут одновременно принять разные решения.

Решение администратора должно быть проверяемым, допускающим исправление и не должно переписывать
историю. На этом этапе оно также не должно само изменять пользователей.

## Решение

- Для неоднозначной строки доступны три явных действия:
  `CREATE_NEW_USER`, `MERGE_SAFE_FIELDS` и `IGNORE_ROW`.
- `MERGE_SAFE_FIELDS` требует UUID кандидата из неизменяемого анализа.
- `CREATE_NEW_USER` разрешён только для `POSSIBLE_MATCH` без совпадения по импортированному телефону.
  Для `CONFLICT` создание отдельного пользователя запрещено.
- Каждое сохранение создаёт новую строку `user_import_row_decisions`. Предыдущие решения не
  обновляются и не удаляются; новая версия ссылается на заменённую.
- Клиент передаёт `expectedDecisionVersion`. Несовпадение с текущей версией возвращает HTTP 409 и
  не создаёт решение или audit.
- Запись результата блокируется в PostgreSQL до повторного чтения текущей версии. Решение и
  `import.row_decided` записываются одной транзакцией.
- Audit содержит идентификаторы, действие и версии, но не содержит исходные персональные данные.
- Строки анализа читаются курсорными страницами до 200 элементов, поэтому администратор может
  обработать все 5000 строк файла.
- Сохранение решения не создаёт и не изменяет пользователя. Проверка актуальности и применение
  решений выполняются отдельным следующим срезом.

## Последствия

- Администратор может исправить своё решение без потери истории.
- Одновременные изменения не перетирают друг друга.
- Снимок анализа остаётся неизменяемым, а решение хранится отдельно от него.
- До реализации финализации импорт является только подготовленным планом изменений.

## Совместимость

Миграция `20260731200000_user_import_row_decisions` только добавляет таблицу, индексы, ограничения и
append-only trigger. Существующие staging batch, анализы и пользователи не изменяются.
