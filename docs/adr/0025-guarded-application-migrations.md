# ADR 0025: Защищенный запуск прикладных миграций

## Статус

Принято.

## Контекст

Репозиторий содержал версионируемые SQL-файлы и PostgreSQL smoke-тест, но рабочие команды
`db:migrate` оставались каркасом. Применение через разные внешние инструменты не защищало от
одновременного запуска, изменения уже примененного файла, пропуска версии или случайного выбора
production.

Историческая таблица `supabase_migrations.schema_migrations` хранит версию и имя, но не SHA-256.
Поэтому проверку целостности нельзя включить для существующей базы без однократного доверенного
снимка ее текущей последовательности.

## Решение

- Порядок миграций определяется единым типизированным манифестом и должен точно совпадать с
  файлами `supabase/migrations`.
- Запускатель использует `DATABASE_DIRECT_URL` и неблокирующий PostgreSQL advisory lock. Второй
  одновременный процесс завершается без ожидания.
- Уже примененные версии обязаны быть точным префиксом локального набора. Неизвестная версия,
  другое имя, пропуск или перестановка останавливают запуск.
- Каждая новая миграция выполняется в отдельной транзакции вместе с записью версии и SHA-256.
- Миграция `20260726200000_application_migration_checksums` создает append-only таблицу
  доказательств. При ее первом применении запускатель фиксирует хеши всех предыдущих известных
  файлов в той же транзакции.
- После создания таблицы отсутствие или несовпадение любого хеша закрывает дальнейшее применение.
- Локальная команда разрешена только для `local` и `test`, команда развертывания только для
  `staging` и `production`.
- Production требует точной фразы подтверждения и отдельных признаков готовой резервной копии и
  проверенного плана отката.

## Последствия

Первое применение checksum-миграции к существующей базе является доверенной точкой отсчета:
запускатель может доказать неизменность файлов только после нее. Перед этим переходом оператор
обязан проверить историю миграций и резервную копию. Для новой базы хеши фиксируются при первом
применении полного набора.

Supabase CLI можно использовать для запуска локальной инфраструктуры, но нельзя параллельно
применять тот же набор прикладных миграций другим процессом. Smoke-тест чистой базы и обновления с
предыдущей схемы использует тот же код запускателя.

## Откат

Код запускателя можно откатить, не удаляя таблицу доказательств. Таблица и ее строки остаются,
поскольку они append-only. Удаление таблицы, триггера или записей является отдельной
разрушительной миграцией и не входит в этот откат.
