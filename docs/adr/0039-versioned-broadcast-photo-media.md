# ADR 0039. Фото в версиях рассылок

## Статус

Принято.

## Контекст

Рассылка должна поддерживать изображение, сохраняя неизменяемую опубликованную версию и единый
контур массовой и тестовой доставки. Загрузка произвольных удалённых файлов через worker увеличила
бы поверхность SSRF, использование памяти и число неоднозначных внешних операций.

## Решение

- Новые и повторно сохранённые черновики используют schema v3.
- Содержимое может включать не более одного медиа-объекта `photo` с абсолютным HTTPS URL длиной
  до 2048 символов, без имени пользователя и пароля.
- Версия фиксирует точный URL. Worker не скачивает изображение и передаёт URL непосредственно
  Telegram Bot API.
- Текст сообщения становится подписью фото. До персонализации редактор допускает не более
  1000 символов, после подстановки worker проверяет предел Telegram 1024 символа.
- HTTPS-кнопки отправляются вместе с фото. Настройка предпросмотра ссылок для фото запрещена,
  поскольку к подписи она не применяется.
- Schema v1 и v2 сохраняют прежнее текстовое поведение.
- Ошибки Telegram при загрузке URL классифицируются тем же адаптером, что и ошибки текстовой
  доставки. Некорректный сохранённый URL является окончательной ошибкой.

## Последствия

- API и worker не получают байты изображения и не становятся прокси для внешнего контента.
- Доступность URL должна сохраняться до завершения кампании и всех повторных попыток.
- Неизменяемость гарантируется для ссылки в версии, но не для содержимого внешнего ресурса.
  Для юридически значимых или строго неизменяемых изображений оператор должен использовать
  URL объекта в хранилище без перезаписи.

## Совместимость

Миграция `20260731040000_broadcast_photo_media_v3` только расширяет допустимые значения
`schema_version` до 3 в версиях и тестовых доставках. Таблицы и существующие строки не
переписываются.
