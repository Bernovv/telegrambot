# ADR 0017: Administrator Immutable Offer Management

## Status

Accepted on 2026-07-26.

## Context

An editable Google document cannot be the legal snapshot accepted by a purchaser. Administrators
need version history and activation controls, while orders must retain the exact version they
received even after a later publication or withdrawal.

## Decision

- Add draft-only publication and withdrawal operations protected by `events.write`, a reason, and
  exact event optimistic version.
- Accept approved plain text plus source metadata. Generate escaped static HTML on the server
  instead of accepting executable administrator HTML.
- Calculate SHA-256 over the exact generated bytes and upload each version to a unique Supabase
  Storage path with overwrite disabled.
- Keep Storage behind an application port and an API-owned adapter. The service-role key remains
  server-only and Storage is disabled by default.
- Serialize the database mutation with the existing `event-sales:<eventId>` advisory lock and event
  row lock.
- Recheck draft state and event version after upload, deactivate only the former version's routing
  flag, append the new immutable version, assign it to the event, increment the aggregate version
  once, and write audit in one transaction.
- Never update published version content or delete a version. Withdrawal clears the event
  assignment and sets `is_active` false.
- Return all versions and acceptance counts in the administrator event projection.
- Keep existing orders pinned to their original offer version.

## Consequences

- A mutable source URL is metadata; Telegram opens the stored immutable snapshot.
- Public snapshot bytes can be cached permanently because a path is never reused.
- Storage upload and PostgreSQL cannot share one atomic transaction. A database conflict after
  upload may leave an unreferenced immutable object, which is harmless to order routing but needs a
  future reviewed orphan-cleanup process.
- PDF upload, rich-text import, source fetching, URL health incidents, and automated orphan cleanup
  remain separate slices.

## Compatibility And Rollback

The existing `offer_documents`, `offer_versions`, immutable trigger, and event foreign key are
reused; no migration is introduced. Rollback removes the handlers, adapter, BFF entries, and
administrator route. Existing objects, versions, assignments, orders, and acceptance evidence
remain valid.
