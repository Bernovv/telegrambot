# ADR 0019: Закрепленные пользовательские сессии сценария

## Статус

Принято 26 июля 2026 года.

## Контекст

После публикации сценария Telegram должен выполнять его одинаково в long polling и webhook.
Новая публикация не должна менять уже начатый диалог. Повторная доставка update, параллельные
callback и подмена идентификатора перехода не должны повторять действие или повреждать сессию.
Финансовые и другие action-узлы пока не имеют утвержденных application-портов.

## Решение

- Создавать `scenario_session` только для опубликованной версии мероприятия и навсегда закреплять
  `scenario_version_id` за сессией.
- Возобновлять открытую сессию по пользователю, мероприятию и каналу; новую публикацию использовать
  только для новой сессии.
- Хранить текущий узел, статус, срок жизни и optimistic `lock_version` в PostgreSQL.
- Хранить trace выполнения в append-only `scenario_events`; update и delete запрещены триггерами.
- Обрабатывать команду и смену состояния в одной транзакции с уникальным idempotency key
  Telegram update.
- Блокировать строку сессии перед переходом и повторно проверять владельца через
  `messenger_identities.external_user_id`.
- Передавать в transport нейтральную модель текста и кнопок. UUID сессии и ребра кодировать в
  compact base64url callback длиной не более 64 байт.
- Выполнять только безопасные узлы представления и ввода: `start`, `message`, `menu`, `choice`,
  `text_input`, `number_input`, `end`.
- Автоматические цепочки ограничивать числом шагов. Неподдерживаемый action-узел блокирует сессию
  без вызова внешнего сервиса и без финансового эффекта.
- Устаревший или чужой переход отклонять без изменения живой сессии.
- Если у мероприятия нет опубликованного сценария, сохранять прежнее Telegram-приветствие.

## Последствия

- Перезапуск приложения не теряет позицию пользователя.
- Старые сессии завершаются на старой неизменяемой версии.
- Повторная доставка одной команды не повторяет сообщения или trace.
- Публикационный валидатор дополнительно проверяет текст, режим переходов presentation-узлов,
  ключ контекста и явные границы input-узлов.
- Заказ, оферта, оплата, кошелек и остальные action-узлы требуют отдельных application-портов,
  idempotency и contract tests до включения в runtime.

## Совместимость и откат

Миграция `20260726160000_scenario_runtime` только добавляет таблицы, индексы, ограничения и
защитные триггеры. Откат приложения возвращает прежнее приветствие при отключенном runtime, не
удаляя сессии и trace. Автоматический откат схемы не выполняется.
