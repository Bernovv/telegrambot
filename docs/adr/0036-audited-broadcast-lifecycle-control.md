# ADR 0036. Аудируемое ручное управление рассылкой

## Статус

Принято.

## Контекст

Оператору нужны пауза, возобновление и окончательная отмена кампании. Команда может конкурировать
с worker и уже арендованной отправкой, поэтому проверка состояния только в HTTP-слое недостаточна.
Каждое административное изменение должно иметь обязательную причину, optimistic locking, аудит и
доменное событие.

## Решение

- Пауза разрешена для `preparing` и `sending`, возобновление только для `paused`, отмена для
  `scheduled`, `preparing`, `sending` и `paused`.
- Репозиторий блокирует агрегат, проверяет `expectedLockVersion` и повторно проверяет переход.
- Переход, append-only audit и одно из событий `BroadcastPaused`, `BroadcastResumed` или
  `BroadcastCancelled` записываются в одной транзакции.
- Ручная пауза очищает автоматическую причину. Возобновление очищает `paused_at`, отмена фиксирует
  `cancelled_at` и является окончательной.
- После паузы или отмены новые delivery-записи не арендуются. Уже арендованная отправка может
  завершить внешний вызов и зафиксировать подтверждённый результат; после отмены новая повторная
  попытка для неё не создаётся.

## Последствия

Команды имеют однозначный порядок относительно операций worker на уровне строки кампании.
Optimistic locking защищает от действий по устаревшему экрану. Отменённую кампанию нельзя
возобновить; для повторной отправки создаётся новая версия рассылки и новый снимок аудитории.
