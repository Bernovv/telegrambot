# ADR 0041. Неизменяемый анализ совпадений импорта пользователей

## Статус

Принято.

## Контекст

После нормализации CSV система должна найти существующих пользователей, но не может считать все
идентификаторы одинаково надёжными. Telegram ID, подтверждённый телефон и CRM ID являются точными
признаками. Username может быть переименован или повторно занят и требует решения администратора.
Повторный анализ на изменившихся данных без фиксации снимка сделал бы предпросмотр
невоспроизводимым.

## Решение

- Для каждого staging batch создаётся не более одного immutable analysis. Повторный запрос
  возвращает существующий результат без новых строк и audit.
- Telegram `external_user_id`, телефон со статусом `verified` и внешний ID системы `crm`
  используются как точные признаки.
- Единственный пользователь с текущим нормализованным Telegram username или импортированным, но
  не подтверждённым телефоном получает `POSSIBLE_MATCH`; эти признаки сами по себе не создают
  точное совпадение.
- Если точные признаки ведут к разным пользователям или username противоречит точному признаку,
  строка получает `CONFLICT`.
- Существующий телефон со статусом `imported` или `verified` защищён от замены. Другой телефон в
  импортируемой строке создаёт `CONFLICT`.
- Пустые поля существующего пользователя дают `MERGE_NEW_FIELDS`. Непустые отличающиеся имя и
  фамилия не перезаписываются и отображаются как предупреждение.
- Анализ хранит только UUID кандидатов, виды совпадений, статусы и безопасные коды причин.
  Персональные данные остаются в исходной staging-строке и не копируются в audit.
- Внешние CRM ID нормализуются в отдельном справочнике `user_external_identities` с уникальностью
  по системе и значению.
- Этот срез не принимает решения администратора и не создаёт, не обновляет и не объединяет
  пользователей.

## Последствия

- Предпросмотр становится воспроизводимым и пригодным для последующего явного решения конфликтов.
- Новые изменения пользовательской базы после анализа не меняют уже показанный снимок.
- Для повторного анализа потребуется новый batch или будущая версионная модель анализа.
- Следующий срез должен хранить решения администратора, проверять их актуальность перед записью и
  выполнять merge ограниченными возобновляемыми порциями.

## Совместимость

Миграция `20260731160000_user_import_identity_matching` только добавляет справочник внешних
идентификаторов, analysis/results и append-only триггеры. Существующие staging, users, contacts и
messenger identities не изменяются.
