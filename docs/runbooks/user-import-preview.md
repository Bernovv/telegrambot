# Предпросмотр и сопоставление CSV-импорта пользователей

## Доступ

- Страница администратора: `/data-operations`.
- API: `POST /api/v1/imports/users/preview`.
- Анализ: `POST /api/v1/imports/users/:batchId/analyze`.
- Строки анализа: `GET /api/v1/imports/users/analyses/:analysisId/rows`.
- Решение по строке:
  `POST /api/v1/imports/users/analyses/:analysisId/rows/:rowNumber/decision`.
- Право: `imports.execute`.

Каждая загрузка, анализ и решение требуют причину. Операции создают audit `import.preview_created`,
`import.match_analyzed` и `import.row_decided`, но не изменяют пользователей.

## Формат

- UTF-8;
- расширение `.csv`;
- размер от 1 байта до 512 КиБ;
- от 1 до 5000 строк данных;
- разделитель: `,`, `;` или табуляция;
- заголовки: `telegram_id`, `telegram_username`, `phone`, `external_crm_id`, `first_name`,
  `last_name`;
- хотя бы один заголовок идентичности:
  `telegram_id`, `telegram_username`, `phone` или `external_crm_id`.

Неизвестные, повторяющиеся заголовки и различное число столбцов отклоняют весь файл.

## Статусы staging

- `NEW` — строка нормализована и уникальна внутри файла;
- `INVALID` — строка содержит неверное значение или не имеет идентичности;
- `IGNORED` — нормализованный дубликат другой строки того же файла.

Статусы предварительные. `NEW` не означает, что пользователь уже создан.

## Статусы сопоставления

- `NEW` — точных или предварительных кандидатов нет;
- `EXACT_MATCH_NO_CHANGE` — точный пользователь найден, новых полей нет;
- `MERGE_NEW_FIELDS` — точный пользователь найден и может быть дополнен пустыми полями;
- `POSSIBLE_MATCH` — найден единственный кандидат только по Telegram username;
- `CONFLICT` — признаки указывают на разных пользователей или расходится защищённый телефон;
- `INVALID` и `IGNORED` — решение staging сохранено без изменений.

Точными признаками являются Telegram ID, подтверждённый телефон и CRM ID. Username и телефон со
статусом `imported` дают только возможное совпадение и требуют решения администратора. Телефоны со
статусом `imported` или `verified` не перезаписываются. Существующие непустые username, имя и
фамилия также сохраняются.

## Решения администратора

Решение доступно только для `POSSIBLE_MATCH` и `CONFLICT`:

- `MERGE_SAFE_FIELDS` — при будущей финализации дополнить только пустые безопасные поля выбранного
  кандидата из снимка;
- `CREATE_NEW_USER` — при будущей финализации создать отдельного пользователя; действие разрешено
  только для `POSSIBLE_MATCH` без совпадения по телефону со статусом `imported`;
- `IGNORE_ROW` — исключить строку из будущего применения.

Решение сохраняется сразу, но пользователя не создаёт и не изменяет. Каждое исправление создаёт
новую append-only версию. Клиент передаёт текущую `expectedDecisionVersion`; HTTP 409
`ADMIN_USER_IMPORT_DECISION_VERSION_CONFLICT` означает, что другой администратор уже сохранил более
новую версию и анализ нужно перечитать.

Первые 200 строк возвращаются вместе с анализом. Кнопка «Показать ещё» читает следующие страницы
по курсору `afterRowNumber`; размер страницы ограничен 200 строками.

## Идемпотентность

Сервис считает SHA-256 исходных байтов. Повторная загрузка тех же байтов возвращает существующий
batch и не создаёт строки или второй audit. Изменение файла создаёт другой checksum.

Для каждого batch создаётся один неизменяемый анализ. Повторный запрос анализа возвращает тот же
снимок и не создаёт второй audit. Изменение пользователей после анализа не пересчитывает результат.

## Хранение и диагностика

Исходный файл не сохраняется. Таблицы `user_import_batches`, `user_import_rows` и
`user_import_row_decisions` append-only и содержат нормализованные данные, hash, безопасные коды
ошибок и версии решений. Audit не содержит исходные персональные данные.

- HTTP 400 `INVALID_ADMIN_USER_IMPORT`: проверьте кодировку, расширение, заголовки, размер и число
  строк.
- HTTP 413 `ADMIN_BODY_TOO_LARGE`: файл превысил лимит BFF.
- HTTP 404 `ADMIN_USER_IMPORT_BATCH_NOT_FOUND`: анализ запрошен для неизвестного batch.
- HTTP 404 `ADMIN_USER_IMPORT_ANALYSIS_NOT_FOUND`: запрошены строки неизвестного анализа.
- HTTP 409 `ADMIN_USER_IMPORT_DECISION_VERSION_CONFLICT`: решение уже изменено другим запросом.
- Повторный batch с меткой «Ранее сопоставлен» является штатным результатом идемпотентности.

Не изменяйте staging, analysis и решения вручную. Финализация, проверка актуальности снимка и
chunked merge пользователей в этом срезе отсутствуют.
