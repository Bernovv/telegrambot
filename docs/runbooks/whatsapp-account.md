# Аккаунт компании в WhatsApp: подключение и проверка

Третий канал разговора после Telegram и MAX, устроенный так же: обычный аккаунт на
корпоративном номере, живущий на сервере, от имени которого менеджеры отвечают из панели.
Бота в WhatsApp у нас нет и не планируется — билеты продаются в Telegram и MAX, здесь только
живой разговор.

Решение от 23.08.2026, фаза 3в плана. Отказ от 21.08 отменён: клиенты этим мессенджером
пользуются, а холодных рассылок мы не делаем — пишем только тем, кто сам зарегистрировался.

## Чем это отличается от двух других каналов

| | Telegram | MAX | WhatsApp |
|---|---|---|---|
| Протокол | MTProto через TDLib | свой клиент по их вебсокету | `baileys`, чужая библиотека |
| Прокси | обязателен | не нужен | **обязателен**, та же машина, что у Telegram |
| Сессия | каталог TDLib | строка токена в `.env` | **каталог с сигнальными ключами** |
| Вход | код из SMS | код из приложения | **код привязки, вводится на телефоне** |
| Опознаватель человека | ник | ник или число | **телефон** |
| Отправка файлов | всё | только картинки | всё |

Две строки здесь заслуживают внимания.

**Библиотека чужая, и это осознанно.** У MAX клиент написан своими руками — там нужно шесть
вызовов. Здесь переписка шифруется сигнальным протоколом с ключами, меняющимися после каждого
сообщения; своя реализация означала бы свою криптографию в проде. Вся библиотека заперта в
одном файле — `packages/messenger-whatsapp-account/src/client.ts`; остальной канал работает
против шести методов порта `WhatsAppSocket`.

**Опознаватель — телефон.** Лучшее, что есть у трёх каналов: разговор сам склеивается с
карточкой, заведённой заявкой с сайта, импортом или Звоноботом. Неопознанных диалогов, как в
Telegram без ника, здесь почти не бывает.

## Что нужно завести один раз

1. **Номер и телефон с приложением.** Номер уже есть. Важно другое: телефон, на котором
   стоит WhatsApp с этим номером, должен **выходить в сеть хотя бы раз в неделю**. Связанное
   устройство живёт без основного телефона около двух недель, дальше отвязывается — и
   привязку придётся делать заново, с телефоном в руках.
2. **Профиль**: имя, аватар, описание — до первого сообщения клиенту. Пустой профиль,
   который пишет незнакомым, собирает жалобы, а жалобы здесь решают всё (см. «Про бан»).
3. **Каталог сессии** с правами `700`:

   ```bash
   install -d -m 700 -o root -g root /var/lib/telegrambot/wa-account
   ```

4. **Прокси.** Отдельной строкой ниже — это первое, что ломается.

## Прокси: та же машина, но своя переменная

WhatsApp с этого сервера напрямую недоступен: домены исключены из национальной системы
доменных имён. Ходим через амстердамскую машину `ams-1-vm-smbv` (`185.11.135.121`), ту же,
что у Telegram-аккаунта: там обычный SOCKS5 (`dante`, порт 11080), и ему всё равно, чей
трафик перекладывать. На самой машине менять нечего — файрвол пускает наш сервер, а ходить
будет он же.

**Переменная своя, а не общая с Telegram.** Значение то же самое, но одна правка не должна
гасить два канала сразу: 27 июля затёртый адрес прокси уже стоил двух часов недоставленных
билетов.

**У WhatsApp два адреса, а не один.** Сообщения идут по вебсокету на `web.whatsapp.com`,
файлы качаются и заливаются обычным HTTPS на `mmg.whatsapp.net`. В коде прокси отдаётся обоим
(`agent`, `fetchAgent` и axios при скачивании). Если однажды вложения перестанут скачиваться
при работающей переписке — смотреть надо сюда.

Проверка живости прокси с нашего сервера:

```bash
curl -x socks5h://tgproxy:ПАРОЛЬ@185.11.135.121:11080 https://api.ipify.org
```

Должен ответить `185.11.135.121`.

## Настройки в `.env`

```
WHATSAPP_ACCOUNT_SESSION_DIR=/var/lib/telegrambot/wa-account
WHATSAPP_ACCOUNT_PHONE=79XXXXXXXXX
WHATSAPP_ACCOUNT_PROXY=socks5://логин:пароль@185.11.135.121:11080
WHATSAPP_ACCOUNT_DEVICE_NAME=Бизнес-Прорыв CRM
```

Канал включается наличием `WHATSAPP_ACCOUNT_SESSION_DIR`. Номер — **только цифры и без
плюса**: именно так его ждёт привязка по коду и так же его возвращает WhatsApp в адресе
человека. Спецсимволы в пароле прокси — процентами: `@` это `%40`, `#` это `%23`.

**Про букву `h` в схеме прокси.** В переменной Telegram её убирали, здесь она не нужна по
другой причине: канал ставит её сам. `socks5://` означало бы, что имя `web.whatsapp.com`
разрешает наш сервер, а домены WhatsApp исключены из национальной системы доменных имён —
имя не разрешится или разрешится не туда, и соединение умрёт молча, при живом прокси. Писать
можно как угодно, работать будет через прокси-резолвинг.

Проверить заполненность: `pnpm env:check`. Без прокси на продакшне процесс не поднимется
вовсе — молча пойти напрямую здесь нельзя.

## Установка зависимостей

Локально локфайл не пересобрать, поэтому первый раз ставится на сервере:

```bash
cd ~/telegrambot && pnpm install
git add pnpm-lock.yaml && git commit -m "Локфайл после установки baileys" && git push
```

**Одна зависимость приезжает из git**, а не из npm: `libsignal` библиотека тянет прямо с
GitHub. Значит, серверу нужен доступ к `github.com` по https и установленный `git`. Если
установка встанет — смотреть надо сюда, а не на npm.

## Привязка

**На том же сервере, где канал будет работать**: сессия привязывается к адресу, с которого
её открыли, и вход с ноутбука с последующей работой из Амстердама — лишний повод
приглядеться к аккаунту.

```bash
cd ~/telegrambot && pnpm wa:login
```

Скрипт печатает код из восьми символов. На телефоне: **WhatsApp → Настройки → Связанные
устройства → Привязка устройства → «Привязать по номеру телефона»** — и ввести код. Вводить
подряд, **без дефисов и пробелов**: поле на телефоне их не принимает.

**Если код не проходит — привязка картинкой:**

```bash
cd ~/telegrambot && pnpm wa:login --qr
```

Это тот же самый способ, которым привязывают веб-версию, и штатный для WhatsApp: код
рисуется в терминале через `qrencode` (`apt install -y qrencode`, если рисовать нечем), на
телефоне его сканируют камерой в том же разделе. Картинка живёт около двадцати секунд.

Первым идёт код, а не QR, по одной причине: его можно продиктовать голосом тому, у кого
телефон, — терминал при этом видеть не обязательно. Но принимается он не всегда, и тогда QR
проходит там, где код не прошёл. С MAX история ровно та же: там вход по коду их антифрод
отверг вовсе, и остался только QR.

После привязки — **резервная копия каталога сессии**. Это не формальность: там сигнальные
ключи, и их потеря означает повторную привязку с телефоном в руках.

```bash
tar czf /root/backups/wa-session-$(date +%F).tar.gz -C /var/lib/telegrambot wa-account
```

## Запуск

```bash
pm2 start deploy/run-whatsapp-account.sh --name whatsapp-account --cwd ~/telegrambot
pm2 save
```

Отдельный процесс, а не часть бота: бот продаёт билеты, и его падение стоит денег, а канал
держит постоянное соединение через прокси за границей.

**Экземпляр должен быть ровно один.** Две копии на одном каталоге сессии — это две программы,
пишущие одни и те же ключи; кончается это испорченной сессией.

## Проверка

**Сначала остановить процесс.** `wa:status` и `wa:whois` открывают своё соединение по тому же
каталогу сессии, и две программы, пишущие одни и те же сигнальные ключи, портят их. У MAX
это обошлось бы лишним устройством в списке, здесь — новой привязкой с телефоном в руках.

```bash
pm2 stop whatsapp-account
```

```bash
pnpm wa:status          # есть ли привязка и есть ли связь
```

```bash
pnpm wa:whois +79001234567   # есть ли человек в WhatsApp
```

```bash
pm2 start whatsapp-account
```

Когда процесс работает, «канал живой?» отвечают журналы, а не скрипт: `pm2 logs
whatsapp-account` — там `account ready` при подъёме и строка с ошибкой на каждый обрыв.

`wa:whois` — это и проверка канала, и то, ради чего аккаунт нужен: по номеру из заявки сразу
видно, дойдёт ли до человека сообщение.

Проверка первого дня, целиком:

1. `pnpm wa:status` — «на связи».
2. Написать аккаунту с постороннего телефона — реплика должна появиться в карточке, а
   карточка найтись по номеру.
3. Прислать фотографию и голосовое — оба должны скачаться (это и есть проверка прокси на
   втором адресе).
4. Ответить из панели текстом и файлом.
5. `pnpm wa:whois` по номеру, которого нет в WhatsApp, — должен честно ответить «не нашлось».

## Про бан

Банят здесь не за автоматизацию как таковую, а за жалобы. Их модели смотрят на долю ответов,
на то, знаком ли получатель, и на ровные интервалы отправки. Наш случай мягкий: пишем тем,
кто сам зарегистрировался на мероприятие, и поштучно.

Но одно место остаётся острым: **первое сообщение незнакомому показывается у него вместе с
кнопками «Заблокировать» и «Пожаловаться»** — они стоят прямо в карточке приглашения. Отсюда
правило, которое не в коде, а в голове менеджера: первая фраза называет, кто пишет и почему
(«вы зарегистрировались на Бизнес-среду 26 августа»). Разница между «понятно» и «кто это и
откуда у них мой номер» — это и есть разница между разговором и жалобой.

Если аккаунт всё же ограничат: переписка у нас, история не теряется, а запасной путь описан в
плане — платный шлюз, где сессия живёт на их стороне. Наш код при этом меняется в одном
файле, потому что канал работает против порта, а не против библиотеки.

## Что канал пока не умеет

- **Написать первым из панели.** Вызов есть и работает в `pnpm wa:whois`, экрана нет. Кусок
  общий с MAX, и делать его стоит один раз на два канала.
- **Групповые чаты** пропускаются намеренно: чужой разговор в карточке человека не нужен.
- **История до подключения** не подтягивается. Разговор начинается с того дня, когда канал
  включили: иначе первая же привязка вывалила бы в ленту переписку за годы.
