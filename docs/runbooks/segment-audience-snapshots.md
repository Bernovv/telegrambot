# Снимки аудитории сегмента

## Доступ

- Страница: `/segments`.
- Список: `GET /api/v1/segments/:segmentId/audience-snapshots`, право `users.read`.
- Детали: `GET /api/v1/segments/:segmentId/audience-snapshots/:snapshotId`, право `users.read`.
- Создание: `POST /api/v1/segments/:segmentId/audience-snapshots`, право `broadcasts.send`.

Создание требует идентификатор опубликованной версии и причину. Черновик использовать нельзя.

## Состояния

- `pending` — заявка ожидает worker;
- `ready` — состав пользователей зафиксирован и неизменяем.

Worker проверяет заявки каждые
`SEGMENT_AUDIENCE_SNAPSHOT_POLL_INTERVAL_MS` миллисекунд и обрабатывает не более
`SEGMENT_AUDIENCE_SNAPSHOT_BATCH_SIZE` снимков за транзакцию.

## Диагностика

- HTTP 422 `ADMIN_SEGMENT_VERSION_NOT_PUBLISHED`: передан черновик, чужая или отсутствующая версия.
- Длительный `pending`: проверьте heartbeat worker, его логи, доступность PostgreSQL и значение
  интервала опроса.
- Повторный запрос при существующем `pending` возвращает ту же заявку и не создаёт дубликат.
- Ошибка SQL оставляет заявку в `pending`, потому что участники и статус откатываются вместе.

## Ограничения

Снимок фиксирует членство по внутренним `user_id`. Текущие имя, имя пользователя Telegram,
статусы и категории в выборке могут измениться после фиксации. Готовый снимок уже можно связать с
неизменяемой версией рассылки. Расписание, фактическая отправка и журнал доставки ещё не
реализованы.
