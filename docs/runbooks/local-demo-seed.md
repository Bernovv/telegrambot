# Локальные демонстрационные данные

## Назначение

Seed создает только синтетические данные для проверки local/test:

- кампанию телефонного бонуса 100 ₽;
- одного демо-пользователя с заведомо синтетическими Telegram ID и телефоном;
- черновик `business-picnic-demo` с тремя продуктами;
- девять правил цен Standard, All-inclusive и детского билета;
- три контентных блока;
- черновик документа оферты с исходной Google Docs ссылкой;
- валидный черновик сценария Standard + optional child → offer → payment.

Он не создает администратора Supabase Auth, не публикует мероприятие и не включает Т-Банк.

## Запуск

1. Запустить локальный PostgreSQL/Supabase.
2. Применить все миграции.
3. Указать в игнорируемом `.env` или текущей сессии:

```bash
APP_ENV=local
DATABASE_DIRECT_URL=postgresql://postgres:postgres@localhost:54322/postgres
DATABASE_SEED_CONFIRM=seed-local-demo-data
```

4. Выполнить:

```bash
pnpm db:seed
```

Для `APP_ENV=staging` и `APP_ENV=production` команда всегда завершается до подключения к базе.

## Повторный запуск

Повторный запуск не изменяет существующие строки. Он проверяет:

- наличие кампании, пользователя и мероприятия;
- ровно три продукта и девять правил цен;
- один draft-документ оферты;
- одну draft-версию сценария;
- валидность graph сценария штатным валидатором.

Если демо-набор изменен или частично удален, команда завершается ошибкой. Она не восстанавливает
строки через `UPDATE` и не удаляет пользовательские изменения.

## Подготовка администратора

Локальный Supabase Auth в текущем `supabase/config.toml` отключен. Для проверки защищенной админки
нужно включить Auth либо использовать отдельный test-проект, создать там пользователя, затем
выполнить `pnpm admin:bootstrap` с его auth subject и точной bootstrap-фразой.

## Публикация демо-мероприятия

1. Открыть черновик Business Picnic.
2. Проверить продукты, правила цен и контент.
3. Открыть черновик сценария, выполнить validation и опубликовать его штатной кнопкой.
4. Создать реальный immutable HTML/PDF snapshot оферты и опубликовать версию.
5. Назначить опубликованные сценарий и оферту мероприятию.
6. Проверить checklist и опубликовать мероприятие.

Source Google Doc из seed не является юридически значимым immutable snapshot.

## Оплата

Т-Банк остается выключенным. Переход в `paid` можно проверять защищенной ручной операцией после
создания заказа. Отдельный `FakePaymentProvider` остается следующим локальным development-срезом.
