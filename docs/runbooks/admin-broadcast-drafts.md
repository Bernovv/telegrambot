# Черновики и версии рассылок

## Доступ

- Страница администратора: `/broadcasts`.
- Список: `GET /api/v1/broadcasts`.
- Детали: `GET /api/v1/broadcasts/:broadcastId`.
- Создание: `POST /api/v1/broadcasts`.
- Сохранение черновика: `PATCH /api/v1/broadcasts/:broadcastId/draft`.
- Публикация: `POST /api/v1/broadcasts/:broadcastId/publish`.
- Планирование: `POST /api/v1/broadcasts/:broadcastId/schedule`.

Все операции требуют административного права `broadcasts.send`. Изменения дополнительно требуют
причину, а сохранение и публикация существующей рассылки — актуальный `expectedLockVersion`.

## Подготовка

1. На странице `/segments` опубликуйте определение сегмента.
2. Зафиксируйте аудиторию и дождитесь состояния `ready`.
3. На странице `/broadcasts` выберите сегмент и готовый снимок.
4. Заполните название, текст, при необходимости фото и HTTPS-кнопки.
5. Укажите причину и сохраните черновик.
6. Проверьте количество получателей и опубликуйте версию.

Публикация фиксирует текст и снимок аудитории. Она не запускает отправку.

## Ограничения содержимого

- текст: от 1 до 4000 символов после удаления пробелов по краям;
- при наличии фото текст является подписью и ограничен 1000 символами до персонализации;
- фото: не более одного, только абсолютный HTTPS URL до 2048 символов без имени пользователя и
  пароля;
- кнопки: не более восьми;
- подпись кнопки: от 1 до 64 символов;
- адрес: только абсолютный HTTPS URL без имени пользователя и пароля;
- один и тот же нормализованный URL нельзя использовать дважды;
- неизвестные поля HTTP-контракта отклоняются.

Schema v2 дополнительно поддерживает:

- `{{first_name}}` — имя;
- `{{last_name}}` — фамилия;
- `{{display_name}}` — отображаемое имя;
- `{{telegram_username}}` — Telegram username с символом `@`;
- запасное обращение от 1 до 64 символов для отсутствующих значений.

Переменные разрешены только в тексте сообщения. Не вводите произвольные конструкции в двойных
фигурных скобках: сохранение такого черновика будет отклонено.

Schema v3 сохраняет возможности персонализации и добавляет одно фото. Для фото предпросмотр
ссылок должен быть выключен. Тестовая отправка использует тот же URL и показывает фактический
результат Telegram до запуска кампании.

## Диагностика

- HTTP 409 `ADMIN_BROADCAST_VERSION_CONFLICT`: данные изменил другой администратор; заново
  откройте рассылку и повторите изменение.
- HTTP 409 `ADMIN_BROADCAST_DRAFT_NOT_FOUND`: публикация запрошена без сохранённого черновика.
- HTTP 422 `ADMIN_BROADCAST_AUDIENCE_SNAPSHOT_UNAVAILABLE`: снимок отсутствует или ещё не готов.
- HTTP 400 `INVALID_ADMIN_BROADCAST`: нарушено ограничение содержимого, идентификатора или причины.

При успешной публикации в той же транзакции должны появиться:

- `audit_log.action = 'broadcast.version_published'`;
- `outbox_events.event_type = 'BroadcastVersionPublished'`;
- новая `lock_version` агрегата;
- указатель `broadcasts.published_version_id` на опубликованную версию.

## Текущие границы

Опубликованную версию можно запланировать после публикации всех более новых черновиков. Worker
подготавливает неизменяемый журнал получателей и счётчики доступных и пропущенных записей.
Фактическая отправка Telegram, повторные попытки, ручное управление, тестовая отправка,
персонализация и одно фото реализованы отдельными контурами. Событие публикации не является
командой массовой отправки.

## Тестовая отправка

На сохранённой рассылке укажите числовой Telegram ID пользователя и причину. Пользователь должен
ранее открыть бота, не блокировать его и оставаться активным в системе. Тест выбирает сохранённый
черновик, а при его отсутствии — опубликованную версию; несохранённые изменения формы не входят в
сообщение.

Состояния `queued` и `sending` обновляются автоматически. `failed` содержит безопасный код ошибки.
`uncertain` означает, что аренда worker истекла без подтверждённого результата: проверьте чат и
только после этого создавайте новый тест.
