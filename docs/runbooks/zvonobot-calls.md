# Звонобот: обратная связь с автообзвона

Робот обзванивает список и спрашивает, интересно ли. Кто нажал кнопку или проговорил дольше
порога — тот новая заявка: человек в базе, карточка в первой колонке воронки «Бизнес-среда»,
звонок в ближайшее окно обзвона. Дальше он идёт по тем же рельсам, что заявка с сайта.

## Что где

| Что | Где |
|---|---|
| Приём вебхука | `POST /api/v1/zvonobot/<ключ>/calls` в `apps/api` |
| Сырьё | таблица `zvonobot_calls`, тело запроса неизменяемо |
| Что считается заявкой | таблица `zvonobot_settings`, одна строка |
| Разбор | проход `zvonobot-calls` в `apps/worker`, раз в минуту |
| Правило звонка | `outreach_task_rules`, повод `zvonobot_feedback` — виден и правится в панели |

Приём и разбор разделены намеренно. Формат вебхука Звонобота подтверждён не до конца:
приёмник обязан принять и сохранить всё, что прислали, даже если разобрать это он не умеет.
Разбор — второй проход по сохранённым строкам, и его можно переписать, когда формат
подтвердится, а потом прогнать по уже принятому.

## Включение

**1. Ключ.** Длинная случайная строка, не короче 16 знаков:

```bash
openssl rand -hex 24
```

Положить в `.env` как `ZVONOBOT_WEBHOOK_SECRET`. Пока переменной нет, путь отвечает `404` и
приёмник не поднимается — это и есть выключенное состояние.

**2. nginx.** Открыть наружу ровно этот путь, на хосте вебхуков:

```nginx
location ~ ^/api/v1/zvonobot/[A-Za-z0-9_-]+/calls$ {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

**3. Адрес в кабинете Звонобота:**

```
https://max-bot.biz-day.ru/api/v1/zvonobot/<ключ>/calls
```

Адрес целиком является секретом — в переписку и в задачи он попадать не должен. Если их
кабинет умеет свои заголовки, ключ можно слать в `X-Zvonobot-Key`, а в адресе оставить
что угодно.

**4. Что считать заявкой.** По умолчанию — нажатая «1». Правится строкой в базе:

```sql
update public.zvonobot_settings
   set lead_buttons = array['1','2'],
       lead_min_duration_seconds = 25,
       updated_at = now()
 where id;
```

`lead_buttons` пустой и `lead_min_duration_seconds` пустой вместе означают «ничего не
считаем заявкой». Это осмысленное состояние: так включают первую кампанию, чтобы сперва
посмотреть, что вообще приезжает.

## Первая кампания

Не на всю базу. Сначала одна кампания на сотню номеров, потом смотрим, что пришло:

```sql
select status, count(*) from public.zvonobot_calls group by status;

select received_at, phone_e164, pressed_button, duration_seconds, payload
  from public.zvonobot_calls
 order by received_at desc
 limit 20;
```

`status`:

- `pending` — приняли, ещё не разбирали;
- `lead` — завели заявку, `contact_id` и `task_id` покажут кого и с каким звонком;
- `ignored` — разобрали, но по правилам это не заявка (или воронки нет);
- `unparsed` — телефон из тела достать не удалось, нужна рука.

**`unparsed` — это главное, на что смотреть после первой кампании.** Значит, телефон лежит
в поле, которого нет в списке имён (`PHONE_KEYS` в `packages/application/src/zvonobot.ts`).
Тело сохранено целиком — по нему видно, как поле называется, и добавление имени в список
это правка одной строки. Уже принятые строки после этого разбираются повторно:

```sql
update public.zvonobot_calls
   set status = 'pending', processed_at = null
 where status = 'unparsed';
```

Так же возвращают в разбор `ignored`, если поменяли правило «что считается заявкой».

## Чего не будет

- **Организаторам не приходит сообщение** на каждую заявку из робота. Кампания даёт их
  пачками, и сообщение на каждую было бы шумом; сигнал — звонок в списке задач, тот же, что
  у заявки с сайта.
- **Тело вебхука нельзя переписать и строку нельзя удалить** — на таблице стоит триггер.
  Спор «что там на самом деле прислали» решается колонкой `payload`, и она первичный
  документ.
- **Звонок не встанет, если по карточке уже открыт другой.** Запланированное менеджером
  главнее автоматики — то же правило, что у всех автозадач.

## Открытый вопрос к Звоноботу

Шлёт ли он вебхук **по каждому звонку** с результатом и нажатой кнопкой, или только сводный
отчёт по кампании. Если только отчёт — приёмник заменяется на выгрузку по расписанию, а всё
остальное (таблица, правила, разбор, воронка) остаётся как есть.
