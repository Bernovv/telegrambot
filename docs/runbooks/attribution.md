# Откуда пришёл человек: метки рекламы

Вся реклама ведёт на лендинг, и **лендинг — единственное место, где метка вообще
существует**. Дальше её надо донести до нас самим: браузер её никуда не передаёт, а задним
числом взять неоткуда. Отсюда вся конструкция.

## Цепочка

1. Человек приходит на `biz-day.ru/...?utm_source=yandex&utm_medium=cpc&utm_campaign=…`.
2. `public/attribution.js` (внешний репозиторий, рядом с лендингом) запоминает метку в
   `localStorage` на 90 дней — **первое касание, не последнее**.
3. Форма заявки отправляет её вместе с именем и телефоном в `POST /api/v1/site/registrations`.
4. Ссылки на ботов на странице получают ту же метку в `?start=source_…__campaign_…` —
   формат, который бот уже понимает.
5. api складывает сырьё в `site_registrations` и заводит строку в `contact_attributions` —
   по одной на человека, `on conflict do nothing`.
6. Отчёт мероприятия в разрезе «откуда» берёт `utm_source`, а если его нет — текстовое поле
   `source` из карточки.

## Почему первое касание

Вопрос, на который отвечает отчёт, — «что привело человека». Привёл его тот источник, по
которому он пришёл впервые. Последнее касание отвечало бы на другой вопрос и приписывало бы
всех, кто вернулся по прямой ссылке или из закладки, каналу «прямой заход» — то есть
показывало бы рекламу бесполезной ровно в той мере, в какой она работает.

Поэтому запись не переписывается ни на лендинге (`localStorage` не трогаем, пока метке
меньше 90 дней), ни в базе (`on conflict (contact_id) do nothing`).

## Что значит пустая метка

Три разных случая, и путать их нельзя:

| Что в базе | Что это значит |
|---|---|
| строки в `contact_attributions` нет | человек появился до августа 2026 или пришёл не через лендинг |
| строка есть, метки пустые | пришёл сам: прямой заход, закладка, рекомендация |
| `utm_source = 'yandex'` | пришёл по рекламе |

Строка с пустыми метками заводится намеренно: «пришёл сам» — это ответ, а не пробел.

## Ограничения, о которых надо знать

- **`localStorage` живёт до чистки браузера.** Человек в приватном режиме или с
  вычищенным хранилищем придёт без метки, даже если кликнул по рекламе. Это неизбежно:
  других способов, не считая cookie с теми же ограничениями, нет.
- **Метка в ссылке на бота ограничена 64 знаками** — предел Telegram. Длинные названия
  кампаний обрезаются до 24 знаков на часть, и в отчёте они будут выглядеть обрезанными.
  Если это мешает, называйте кампании в Директе короче.
- **Яндекс с автоматической разметкой** ставит только `yclid` без utm. Такой заход
  записывается как `yandex / cpc` без кампании — лучше, чем «прямой», но хуже, чем с
  разметкой. В Директе стоит включить разметку явно.
- **Заявка без карточки метку сохраняет**: она лежит в самой `site_registrations`. Если
  человека потом заведут руками, метку можно перенести глазами — автоматически этого не
  происходит.

## Проверить, что работает

Открыть лендинг с меткой и посмотреть, что запомнилось:

```
https://biz-day.ru/weekly.html?utm_source=test&utm_medium=cpc&utm_campaign=proverka
```

В консоли браузера: `window.bpAttribution.value`. Затем оставить заявку и посмотреть:

```sql
select display_name, utm_source, utm_medium, utm_campaign, created_at
  from public.site_registrations
 order by created_at desc limit 5;
```

Метка у карточки человека:

```sql
select contact.display_name, attribution.*
  from public.contact_attributions attribution
  join public.outreach_contacts contact on contact.id = attribution.contact_id
 order by attribution.recorded_at desc limit 10;
```

Ссылка на бота: навести на кнопку и посмотреть адрес — в нём должен появиться
`?start=source_test__campaign_proverka`.
