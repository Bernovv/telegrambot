# Прикладные миграции PostgreSQL

## Перед запуском

1. Проверить изменения SQL и убедиться, что манифест `packages/database/src/migrations.ts`
   содержит те же файлы в том же порядке.
2. Выполнить `pnpm db:migrations:check`, тесты и проверку типов.
3. Убедиться, что `DATABASE_DIRECT_URL` указывает на нужную базу. Значение URL не выводить в
   терминал, тикет или журнал.
4. Остановить другие процессы применения схемы. Запускатель дополнительно проверит advisory lock.
5. Для production создать и проверить резервную копию, определить точку возврата к предыдущей
   версии приложения и проверить план восстановления.

## Локальная база

Запустить Supabase или локальный PostgreSQL, задать:

```bash
APP_ENV=local
DATABASE_DIRECT_URL=postgresql://postgres:postgres@localhost:54322/postgres
```

Затем выполнить:

```bash
pnpm db:migrate
```

Повторный запуск безопасен: при актуальной схеме команда не применяет SQL повторно.

## Тестовый стенд

Для staging задать `APP_ENV=staging` и прямой URL базы, затем выполнить:

```bash
pnpm db:migrate:deploy
```

После завершения проверить `/health/ready`, журналы API и фонового процесса, а также критический
путь заказа без реального списания.

## Production

Запуск разрешен только при одновременных значениях:

```bash
APP_ENV=production
DATABASE_MIGRATION_CONFIRM=apply-production-migrations
DATABASE_BACKUP_CONFIRMED=true
DATABASE_ROLLBACK_PLAN_CONFIRMED=true
```

Команда:

```bash
pnpm db:migrate:deploy
```

Эти переменные подтверждают выполненные оператором действия, но не создают резервную копию и не
проверяют восстановление автоматически.

## Остановки и восстановление

- Сообщение о занятом lock: найти другой процесс миграций и дождаться его штатного завершения. Не
  снимать PostgreSQL lock вручную без проверки сессии.
- Неизвестная или пропущенная версия: остановить развертывание и сравнить историю базы с
  репозиторием. Не добавлять фиктивную строку в `schema_migrations`.
- Несовпадение SHA-256: считать примененный файл измененным или репозиторий неверным. Не обновлять
  хеш вручную; восстановить исходный файл из проверенного коммита.
- Ошибка SQL: транзакция текущего файла откатывается. Исправление выпускается новой миграцией;
  опубликованный файл не редактируется.
- Ошибка первого доверенного снимка: не продолжать запуск. Сверить все записи
  `supabase_migrations.schema_migrations`, SQL-файлы и резервную копию.

Откат приложения выполняется на совместимую предыдущую версию кода. Разрушительное удаление
колонок, таблиц или checksum-доказательств не выполняется автоматически.
