# Рассылка от рабочего аккаунта Telegram

Кружки, текст и фото уходят участникам мероприятия от рабочего аккаунта
(`@manager_bizproriv`, `+79934828408`), а не от бота. Решения владельца от 19.11.2026:
пишем **участникам мероприятия**, содержимое берём **из «Избранного»**, темп **быстрый**:
одно сообщение в 20–30 секунд, до 150 человек в сутки.

## Как пользоваться

1. С телефона, где открыт рабочий аккаунт, запишите кружок (или напишите текст, или
   пришлите фото) и отправьте его в **«Избранное»**. Сообщений может быть несколько: кружок,
   потом текст.
2. Панель → мероприятие → «Рассылка» → **«От рабочего аккаунта — с кружками»**
   (адрес `/broadcasts/account`). Через несколько секунд сообщение появится в блоке
   «Что отправить». Если нет, нажмите «Обновить».
3. Отметьте до пяти сообщений. Уйдут они **в том порядке, в каком лежат в «Избранном»**:
   Telegram копирует пачку только по возрастанию номеров.
4. Выберите мероприятие. Панель покажет, сколько участников, у скольких есть переписка с
   аккаунтом, скольких нет в Telegram и скольких ещё не проверяли.
5. **Сначала пробная.** Впишите свой `@ник` или телефон и нажмите «Отправить пробную». Если
   у вас ещё нет переписки с рабочим аккаунтом, напишите ему со своего Telegram любое
   сообщение: пробная идёт только туда, где ветка уже есть.
6. «Запустить рассылку». Остановить можно в истории внизу. Уже ушедшее не отзывается.

Копия уходит **без пометки «переслано»**, в родном качестве, с тем же оформлением текста.
Подстановок вроде `{имя}` нет: текст одинаковый у всех.

## Кому уходит

Участники мероприятия: заявки с сайта и заведённые руками (`event_participants`),
покупатели бота (`orders`, оплачен, не исключён). Дубли по `merged_into_contact_id`
схлопываются, архивные контакты пропускаются.

Написать можно **только тем, у кого есть ветка переписки с аккаунтом** в Telegram. Её
заводит проверка номера (`contact_channel_lookups`, сама и понемногу) или первое сообщение
самого человека. Остальные видны в панели как «нет в Telegram» и «номер ещё не проверен».

Список получателей **снимается в момент запуска** и дальше не меняется. Кто уже получил
хотя бы одно из выбранных сообщений в прошлой рассылке, второй раз его не получит. По одному
мероприятию одновременно идёт только одна рассылка.

## Темп и защита аккаунта

Через этот же аккаунт идут ответы клиентам и приветствия. Если Telegram его ограничит,
встанет всё. Поэтому:

| Правило | Настройка | По умолчанию |
|---|---|---|
| Пауза между получателями, случайная в границах | `ACCOUNT_BROADCASTS_PAUSE_MIN_MS`, `_MAX_MS` | 20–30 с |
| Потолок за скользящие сутки (пробные не считаются) | `ACCOUNT_BROADCASTS_DAILY_LIMIT` | 150 |
| Окно, когда пишем | `ACCOUNT_BROADCASTS_WINDOW_START`, `_END`, `_TIMEZONE` | 10:00–21:00 МСК |
| Повторы при сбое сети | `ACCOUNT_BROADCASTS_MAX_ATTEMPTS`, `_RETRY_DELAY_MS` | 3, с 10 минут |
| Пауза после ограничения аккаунта | `ACCOUNT_BROADCASTS_ACCOUNT_PAUSE_MS` | сутки |
| Выключатель | `ACCOUNT_BROADCASTS_ENABLED` | `true` |

Пробная уходит в любое время и вне очереди.

Рассылки идут **по очереди**, старшая первой. Большая рассылка на 300 человек займёт два дня,
и следующая начнётся после неё.

### Что делает отправитель с ответами Telegram

| Ответ | Что происходит |
|---|---|
| `Too Many Requests: retry after N`, `FLOOD_WAIT_N` | пауза **всех** рассылок на N секунд, человек остаётся в очереди |
| `PEER_FLOOD`, `USER_BANNED_IN_CHANNEL` и похожее | **пауза на сутки**: Telegram ограничил аккаунт за спам |
| приватность, блокировка, удалённый аккаунт, платные сообщения | этому человеку «не дошло», без повторов |
| сообщение пропало из «Избранного» или его нельзя копировать | рассылка **останавливается**: остальным ушло бы то же |
| всё остальное | повтор через 10, 20 минут, потом «не дошло» |

**Если в истории написано «Telegram ограничил аккаунт»**, откройте @SpamBot с рабочего
аккаунта и посмотрите, что он отвечает. Пока ограничение действует, писать незнакомым
бесполезно, и отправитель стоит сам. Ответы тем, кто пишет первым, при этом обычно
работают.

**Не удаляйте из «Избранного» то, что сейчас рассылается**: рассылка остановится с
причиной «сообщение удалили из „Избранного“».

## Как это устроено

- `tg-account` каждые 30 секунд (и сразу, как в «Избранное» что-то пришло) читает последние
  30 сообщений «Избранного» в `account_saved_messages`. Кружки, фото, голосовые и видео в
  пределах `CONVERSATION_FILES_MAX_BYTES` (50 МБ; без `CONVERSATION_FILES_DIR` файлы не качаются, а рассылка всё равно уходит) скачивает к нам, **одной копией** на сообщение.
- Рассылка: `account_broadcasts` (что и кому), `account_broadcast_parts` (из каких сообщений),
  `account_broadcast_recipients` (снимок получателей и судьба каждой копии).
- `tg-account` берёт одного получателя за проход и копирует сообщения через
  `forwardMessages` с `send_copy`. Подтверждения ждёт так же, как у ответов из панели.
- Ушедшее ложится в ленту переписки человека как реплика менеджера, запустившего рассылку,
  с вложением, которое ссылается на ту же копию кружка. В карточке появляется касание
  «сообщение отправлено». У пробной касания нет.

## Что смотреть

```sql
-- Идущие рассылки и пауза аккаунта
select id, target_event_id, is_test, status, paused_until, pause_reason, created_at
  from public.account_broadcasts order by created_at desc limit 10;

-- Судьба получателей одной рассылки
select status, count(*) from public.account_broadcast_recipients
 where broadcast_id = '<id>' group by 1;

-- Почему не дошло
select failure_reason, count(*) from public.account_broadcast_recipients
 where status = 'failed' group by 1 order by 2 desc;

-- Сколько ушло за сутки (потолок)
select count(*) from public.account_broadcast_recipients r
  join public.account_broadcasts b on b.id = r.broadcast_id
 where r.status = 'sent' and r.sent_at > now() - interval '1 day' and not b.is_test;

-- Что аккаунт видит в «Избранном»
select kind, left(body, 60), duration_seconds, file_status, sent_at, synced_at
  from public.account_saved_messages where deleted_at is null order by sent_at desc limit 10;
```

Логи: `pm2 logs tg-account | grep -E "account broadcast|saved messages"`.

## Если «Избранное» в панели пустое

- `pm2 ls`: процесс `tg-account` запущен и не перезапускается по кругу.
- `pm2 logs tg-account --lines 50`: есть `account ready` и нет `saved messages sync failed`.
- Миграция `20260901090000_account_broadcasts` применена.
- После обновления кода `tg-account` перезапущен: старый процесс про «Избранное» не знает.
